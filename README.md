# 麦麦卡路里省钱下单助手

> 在「热量目标 + 预算上限」双约束下，帮你从麦当劳菜单里挑出一份**热量合适、价格划算**的组合——**顺手把套餐也拆开算清楚**——确认后陪你把单下完。

[麦当劳程序员创意开发大赛](https://github.com/M-China/mcd-developer-innovation-challenge) 参赛作品 · 由 WorkBuddy 开发

---

## 它解决什么问题

想吃麦当劳，但有两件事同时卡着你：

1. **热量**：我这一餐想控制在 550 kcal 左右。
2. **预算**：我不想超过 28 块。

翻菜单算热量、比价格、查券、还要判断"套餐到底划不划算"——四件事凑一起，没人愿意干。这个助手把它变成一句话：

> "我想吃麦当劳，550 大卡以内，28 块以内，深圳科技园附近。"

它会回你（**真实 MCP 数据，深圳同方信息港门店**）：

| 方案 | 组合 | 热量 | 价格 |
|---|---|---|---|
| 最贴热量 | **人气经典随心配**（套餐） | 576 kcal | **14.9 元** |
| 最省钱 | **精选超值随心配**（套餐） | 502 kcal | **13.9 元** |
| 最平衡 | 麦辣鸡腿汉堡（单点） | 485 kcal | 22.5 元 |

注意：两档最划算的答案都是**套餐**，而且只要 14 元左右。

## 三个不一样的地方

### 1. 套餐不是黑盒，是拆开算的

营养表里没有"三件套"这种组合餐，所以很多同类工具直接把套餐跳过了。我们反过来做：用 `query-meal-detail` 把套餐拆成组件，**按组件热量求和**，再把套餐当成一个完整候选丢进比价池。

结果就是——套餐的钱省在哪、热量花在哪，一目了然：

```
麦辣鸡腿汉堡三件套        33.5 元   921 kcal
├─ 麦辣鸡腿汉堡  485 kcal
├─ 中薯条        289 kcal
└─ 可乐中杯      147 kcal
单点合计 46 元 → 等于省了 12.5 元
```

默认组件恰好在营养表里查不到时（实测"可乐麦炫酷"就没有），引擎会在**同一选配轮次**里改选一个"有营养数据、与默认项名称最像、差价接近最低"的组件（默认可乐会被换回"可乐中杯"，而不是柠檬茶），并明确标出替换记录与 `price_estimated`，提醒复价——**不猜、不糊弄**。

### 2. 双约束求解，给的是一组方案，不是一个答案

热量和预算常常互相打架，通常没有唯一解。所以输出是一组带标签的选项：

`最贴热量` / `最省钱` / `最平衡` / **`套餐优选`**（套餐单独占一档，因为套餐通常更便宜）

取舍摆明给你看，选哪个你说了算。

### 3. 不回避"凑不出来"

目标达不成时，它给你几个可执行方向（放宽热量 / 换低卡主食 / 拆成轻组合），而不是硬塞一个离谱的组合。也不会对你说"你目标定得太苛刻了"——只讲菜单，不评价人。

## 它怎么说话

这个助手是一位**温柔、知心、会算账的姐姐**，不是一台报数机器。她的节奏是：
**先接住你的心情 → 再把数字轻轻放上来 → 最后把决定权还给你。**

> **你**：「中午想吃麦当劳，550 大卡以内，28 块以内，深圳科技园附近。」
>
> **麦麦**：「550 大卡、28 块，这个区间我替你算过了——「精选超值随心配」正好落在里面：502 大卡、13.9 元，比单点省下 11.5 元。要是想吃得饱一点，「人气经典随心配」576 大卡、14.9 元也在你的预算里。你看看合不合心意，不着急的。」

目标凑不出来的时候，她会说：

> 「这个目标定得挺认真的，我先说在前面——它确实有点难为这家店的菜单了。500 大卡以内，能选的主食只有麦香鱼和麦香鸡两款，选择面窄了些。别急，我给你三条路，你挑一条最顺手的就好。」

**温柔 ≠ 纵容。** 她不会评价你的身材，不会劝你"多花点钱买开心"，也不会替你下决定——只把真实的数字如实告诉你，剩下的你说了算。

## 目标用户

- 控卡但要外食的上班族、健身人群
- 预算敏感的在校学生
- 想吃套餐但怕热量超标的人
- 想吃得明白、不想每次都重算一遍的人

## 安装

### 1. 拿到麦当劳 MCP Token

访问 [open.mcd.cn](https://open.mcd.cn)，用手机号登录 → 右上角「控制台」→ 激活并复制 MCP Token。

### 2. 配置 MCP

在 WorkBuddy 左侧边栏【专家·技能·连接器】→【连接器】→ 右上角【自定义连接器】→【配置 MCP】，填入 `mcp-config.example.json` 的内容（把 `${MCD_MCP_TOKEN}` 换成你的 Token）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

保存后回到【自定义连接器】，把 `mcd-mcp` 启用。

### 3. 安装本 Skill

```bash
git clone https://github.com/winkychannn/mcd-calorie-order-saver.git \
  ~/.workbuddy/skills/mcd-calorie-order-saver
```

> 或者直接把仓库目录复制进 `~/.workbuddy/skills/`。技能入口是根目录的 `SKILL.md`。

## 使用示例

**例 1 · 一句话给目标**

> 我中午想吃麦当劳，帮我控制在 550 大卡、28 元以内。

**例 2 · 只给热量**

> 减脂期，400 大卡以内的麦当劳能吃什么？

**例 3 · 带上门店和券**

> 深圳科技园附近，帮我搭一份 600 大卡以内的，看看有什么券能用。

**例 4 · 想吃套餐但怕热量超**

> 想吃三件套，但热量别超过 800 大卡，帮我看看哪个划算。

## 工作流

```
用户给「热量目标 + 预算」
        │
        ├─ 1. 定位门店        query-nearby-stores
        ├─ 2. 拉菜单          query-meals
        ├─ 3. 拉营养表        list-nutrition-foods
        ├─ 4. 拆套餐          query-meal-detail   ← 组件热量求和
        │      ↓
        │   scripts/optimize.py  ← 归一化匹配 + 套餐拆解 + 双约束组合搜索
        │      ↓
        ├─ 5. 券匹配          available-coupons / query-my-coupons
        │                     query-store-coupons
        ├─ 6. 确认门店与取餐方式  query-nearby-stores / delivery-query-addresses
        ├─ 7. 复价确认        calculate-price
        └─ 8. 下单            create-order → 支付链接
```

## 引擎单独跑

`scripts/optimize.py` 不依赖任何第三方库，也不需要联网——MCP 数据由 Agent 取好后通过 stdin 传入：

```bash
python3 scripts/optimize.py < tests/sample-input.json
```

**输入**：`target_kcal` / `budget_yuan` / `kcal_tolerance` / `nutrition[]` / `meals[]` / `combos[]`

套餐支持两种给法，任选其一：

```jsonc
// 给法 A：Agent 已按套餐详情选好组件（价格最准）
{ "code": "9900004064", "name": "精选单人餐三件套", "price": 34.5, "single_sum": 46,
  "components": [ {"code":"1406","name":"板烧鸡腿堡","role":"main"},
                  {"code":"4810","name":"中薯条","role":"side"},
                  {"code":"3050","name":"可乐中杯","role":"drink"} ] }

// 给法 B：直接贴 query-meal-detail 的 rounds，由引擎自动挑组件
{ "code": "9900013304", "name": "人气经典随心配", "price": 14.9,
  "rounds": [ {"name":"蓝区","choices":[{"code":"1120","name":"双层吉士汉堡","isDefault":1,"diffPrice":"+ ¥0"}]},
              {"name":"粉区","choices":[{"code":"521328","name":"可乐麦炫酷","isDefault":1,"diffPrice":"+ ¥0"},
                                        {"code":"3050","name":"可乐中杯","isDefault":0,"diffPrice":"+ ¥0"}]} ] }
```

**输出**：`matched` / `matched_combos` / `unmatched` / `plans`（带标签的方案）/ `advice`（凑不出来时给方向 + 套餐省钱榜）

### 实测回归（真实数据）

| 目标 | 最贴热量 | 最省钱 | 套餐优选 |
|---|---|---|---|
| 550 kcal / 28 元 | 人气经典随心配 576kcal 14.9元 | 精选超值随心配 502kcal 13.9元 | — |
| 700 kcal / 30 元 | 麦香鸡+新地 651kcal 29元 | 人气经典随心配 576kcal 14.9元 | 精选超值随心配 502kcal 13.9元 |
| 200 kcal / 15 元 | 麦香鱼 325kcal（触发"凑不出来"分支） | 精选超值随心配 13.9元 | 人气经典随心配 14.9元 |
| 900 kcal / 40 元 | 巨无霸+那么大鸡排 898kcal 39.5元 | 麦香鸡+那么大鸡排 754kcal 31元 | 精选单人餐三件套 34.5元（省 11.5 元） |

营养表没有的餐品（龙焰鸡腿堡、高达吉士双牛堡、蓝莓爆爆珠麦旋风等 12 项）**如实标注"营养表无匹配"，没有编造热量**。

## 设计取舍

- **显式排除积分抵扣**。`calculate-price` 没有积分参数，积分也不能直接抵现，要抵扣只能走"积分商城兑换餐品券 → 券用于订单"这条重链路。它与"卡路里 + 省钱"的主题关联度低，且会让主流程变长，所以本项目聚焦在**券 + 套餐拆解**上。用户问起时会一句话说明，不做虚假承诺。
- **第一版只做到店自取**（`beType=1`）。链路最短、参数最少，麦乐送/得来速在 `references/mcp-playbook.md` 里留了扩展说明。
- **范围控制在 3~6 个套餐**。全量拆解会让单次对话工具调用过多，按"预算附近 + 标签含爆款/超值/立省"优先拆。

## 合规与免责

- 本助手定位**理性控热量、均衡搭配、聪明消费**，不宣扬不健康饮食、奢靡浪费或拜金主义。
- 不对用户身材、体重做任何评价，不提供医疗或营养专业建议。
- 推荐话术里**不出现**"多花钱买开心""别对自己太苛刻"这类可能诱导超支的表达。
- 所有推荐仅供参考；餐品信息、价格及供应状态以麦当劳官方渠道的实时结果为准。
- 下单是真实消费动作，本助手**只在用户明确确认后**才会创建订单。
