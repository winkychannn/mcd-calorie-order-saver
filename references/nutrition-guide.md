# 热量与搭配参考

给引擎和话术提供"常识边界"，避免出现离谱推荐。

## 一、单餐热量参考区间

| 场景 | 参考区间 | 说明 |
|---|---|---|
| 轻食 / 加餐 | 200 ~ 400 kcal | 小食 + 饮品，或一个卷 |
| 常规正餐 | 450 ~ 700 kcal | 一个主食 + 小食/饮品 |
| 大餐 / 训练后 | 700 ~ 1000 kcal | 双层堡 / 安格斯 + 配餐 |

- 用户没给目标时，默认按 **500 kcal** 起步。
- 容差默认 **±20%**（`kcal_tolerance=0.20`），即 500 kcal 目标下 400~600 kcal 都算达标。
- 若用户给的目标明显低于 200 kcal，先提醒"这个目标低于单餐常见下限"，并按分支 A 给方向，**不要**硬凑。

## 三、套餐配比常识（本助手会把套餐拆开算）

| 套餐结构 | 常见组件 | 合计热量 | 说明 |
|---|---|---|---|
| 三件套 | 主食 + 中薯条 + 中杯饮料 | 750 ~ 950 | 一个成年人的正餐量，热量不低 |
| 随心配（1+1） | 一个主食/小食 + 一个饮料/甜品 | 450 ~ 550 | 轻量正餐，价格最友好 |
| 四件套 / 小食盘 | 主食 + 小食 ×2 + 饮料 | 900 ~ 1400 | 适合两人或大胃口 |
| 单人餐 | 主食 + 小食 + 饮料（与三件套近似） | 750 ~ 950 | — |

**关键结论**：套餐的**价格**几乎总优于单点（实测"三件套"比单点省 10 元以上），但**热量**通常明显高于 500 kcal 档。所以：
- 目标是 500~600 kcal 时，**随心配类套餐**往往是最优解（便宜且热量合适）；
- 目标是 700 kcal 以上时，**三件套**开始变得有竞争力；
- 想压低热量又想吃套餐，**换组件**（薯条→玉米杯、可乐→无糖可乐）是首选手段。

## 四、搭配原则（写进推荐语时可引用）

1. **蛋白质优先**：同热量下，蛋白质高的组合更抗饿。麦香鱼、板烧鸡腿堡、麦麦脆汁鸡的蛋白质热量比都不错。
2. **饮品是"最便宜的调档工具"**：把可乐换成无糖可乐 / 美式 / 锡兰红茶，能直接砍掉 100~150 kcal，价格几乎不变。**这是达成低热量目标的首选手段。**
3. **小份优于大份**：薯条、玉米杯都有大小杯，热量差可达 100 kcal，价格差通常只有 1~2 元。
4. **酱料单独算**：蘸酱 3 元一份，热量另计，不要默认包含在推荐里。
5. **避免"热量凑数"**：不要为了凑够目标热量推荐纯糖饮品（可乐大杯 224 kcal），优先用有蛋白质或膳食纤维的小食（玉米杯、苹果片、麦乐鸡）。
6. **套餐先拆再比**：看到"套餐"别直接跳过——拆成组件算热量，往往能同时拿到"更便宜"和"热量可控"。

## 五、引擎输出字段含义

| 字段 | 含义 |
|---|---|
| `kind` | `assemble`（自选组合）/ `combo`（套餐） |
| `kcal` | 组合总热量（套餐为各组件热量之和） |
| `kcal_gap` | 与目标的差值（正=超目标，负=低于目标） |
| `kcal_pct` | 达成度百分比 |
| `within_kcal` | 是否落在容差区间内 |
| `within_budget` | 是否在预算内（基于菜单价，未含券） |
| `tag` | 最贴热量 / 最省钱 / 最平衡 / 套餐优选 / 备选 |
| `components` | 仅套餐有：拆解后的组件清单（含各自热量） |
| `substituted` | 仅套餐有：为拿到营养数据而替换过的组件（如 `可乐麦炫酷 → 可乐中杯`）。替换时优先选与默认项名称最像的，再比差价 |
| `price_estimated` | 发生替换时为 `true`，提示第 5 步必须复价 |
| `savings_vs_single` | 仅套餐有：相对各组件单点合计省下的钱（元） |

> `within_budget` 用的是**菜单价**。含券终价以 `calculate-price` 为准，通常会更低。
